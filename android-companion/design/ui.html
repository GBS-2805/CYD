OFF-SITE — phone app, UI file

This is the whole app, drawn as one static page. Seven screens, at the reference phone's 393 × 852 dp, using the same dp, sp, radii and colours the Android views use. No build step: open this file in any browser and edit it.

Edit it however you like — but keep the file honest. Every measurement here was copied from the Java, so a number you change is a number I can implement. The variables at the top of the <style> block are the Ui constants, one for one; the class names are the view-building methods. When you hand it back, I read the diff, change the Java, rebuild the APK and paste fresh renders of every screen I touched back into the chat. tokens.json in this folder is the same numbers as data, which is what makes "make the cards 12dp round" a checked change rather than a guess.

Screens marked fold are taller than the glass: the dashed line at 852px is the bottom of the screen, and anything under it is reached by scrolling. It is drawn here rather than clipped so you can still edit it.

Everything is monospace — the deck is a terminal, so the phone reads as the same instrument. Letter-spacing is Android's em value, so it is the same number here.

Copy

Strings worth keeping verbatim, because they carry the tone: the status line IDLE · BRIDGE STOPPED / SCANNING / LINKED · <DEVICE>; the serial hint Plug the CYD in with an OTG cable, then tap PROBE.; the empty log Nothing yet. PROBE and FLASH write each handshake step here, and a quiet ROM reports the raw bytes it did send.; the privacy line The deck sits where other people can read it. Pick the apps it may show.; and the shelf's own promise, Alphabetical. Tap a name for its notes.

Handing it back

  1. Edit this page (or tokens.json, if it is only numbers).
  2. Tell me what you changed, in words, in the chat — "cards at 12dp, ditch the chips, the crumb should be sentence case".
  3. I change the Java, rebuild the APK, regenerate the renders from the same numbers and paste every touched screen inline in the chat.
  4. If a render disagrees with this file, the render wins for the phone and this file gets corrected — they must not drift apart.
